# 写真記録（無料枠優先・既存機能維持）

## 実装済み
- 作業カレンダーの日付右上に「📷」を追加。数字はその日に関連する写真の総数。
- 作業履歴（作業ID）、作物管理（作物ID）、圃場管理（圃場ID）に写真リンクを追加。
- 1記録につき5枚まで、1枚5MBまで。JPEG / PNG / WebPのみ。
- 撮影・記録日と短いメモを保存し、日付別一覧からも閲覧可能。
- 写真の閲覧・登録・削除には既存ログインが必要で、同じ農場データキーに限定。
- 本体画像はSupabase Storageへ保存し、Neonには参照情報だけを保存。
- データベース全体の登録済み写真合計が800MiBに近づいたらアップロードを停止。
- Render通常のローカルファイル領域には写真を置かない。

## 初回だけ必要な無料設定
1. https://supabase.com/ にサインアップ（Freeプランを選択）。**支払いが発生する有料プランは選択しない。**
2. 新しいSupabaseプロジェクトを作成。
3. Storage > New bucketで **farm-photos** という名前をつけ、必ず **Public bucket = OFF**（非公開）にする。
4. Supabaseプロジェクトの「Project URL」と、秘密の **service_role** キーを表示。
5. Render > farm-management-system > Environmentに以下を設定：
   - SUPABASE_URL = https://<project-ref>.supabase.co
   - SUPABASE_SERVICE_ROLE_KEY = Supabaseのservice_roleキー
6. Render環境変数は **Secret** として扱い、GitHub・ブラウザ・ChatGPTの会話にはキーを貼らない。
7. 設定後にRenderが再デプロイされたら、カレンダーの日付の「📷」から写真登録を確認。
8. 未設定時は「保存先を設定中」と表示し、誤ってRenderローカルへ写真を保存しない。

## 運用・費用
- 現在のRender契約はそのまま（料金プランを勝手に変更しない）。
- Supabase無料枠内で利用する。アプリの800MiB制限は*容量*のための予防策であり、帯域・操作回数等の無料上限までは保証できない。
- 無料枠や利用規約はサービス側で変更される場合があるため、SupabaseのUsage画面も定期的に確認する。
- **非公開バケットを使用**し、署名付きURL・公開URLをブラウザへ配らない。
- service_roleキーはサーバー環境変数からのみ利用。漏えいした場合はSupabase側でローテーションする。

## 注意点・動作確認
- この機能を使うにはSupabaseプロジェクトとRenderの環境変数設定が必要。
- 写真を持つ作物・圃場・作業を後から削除しても、画像は日付別一覧に残る。必要に応じて日付別一覧から写真を削除する。
- JPEG等のEXIF位置情報は削除していないため、必要に応じてアップロード前に位置情報を除去する。
- URL /farm-photos/{photoId}/file はサーバー側でログイン・農場をチェック。
- 画像の Content-Type はファイル名ではなく画像の先頭バイトを使って検証。
- 本番デプロイ前にMavenビルド、プライベートバケットの確認、スマホ/PCからのアップロード、別農場アカウントによる閲覧禁止、削除確認を実施。
- 写真機能以外の既存データ・メニュー・操作を削除する変更はしていない。

## ロールバック
GitHubの導入前コミットを保持し、環境変数を外すと写真アップロード機能は停止する。
DBに追加される farm_photo テーブルは既存のデータを削除しない。
